# 哼记性能优化记录

日期：2026-10-24。工程已原地更新，使用原 AppID 本地编译和模拟器验证。

## 实际改动

- 首页首次仅载入 20 条轻量摘要，上拉继续加载。摘要不携带完整音符或录音路径，未变化的返回首页不重复刷新。
- 摘要索引与原始记录分开保存，兼容旧数据；修改前先标记 dirty，摘要写入或草稿清理失败时保留标记，后续从原始记录重建。原始灵感、录音、未完成草稿继续保留。
- 录音权限、音频解码和音高识别模块在使用时加载；进入编辑页时也不立即创建音频实例，MIDI 编码在导出时加载。
- 钢琴卷帘缓存不变的背景网格，音符与清单共用一份视图数据。拖动按数组下标增量更新，选中状态放在对应音符上；跳过无变化的重绘，避免每步序列化两份完整音符数组。
- 试听合成、限幅和 WAV 编码按约 8ms 的计算预算让出事件循环，支持中途停止。每个播放器最多保留一份试听文件缓存，音符、BPM 或音色改变后重建；销毁时只清理自己的临时文件。各次写文件路径独立，过期写入不能覆盖新试听。
- YIN 在找到首个合格谷值及其插值右邻后停止计算无用滞后项；完整有效帧直接读取 Float32Array，尾部继续按原规则补零。识别按约 10ms 预算分段，避免固定每 24 帧等待所产生的额外延迟。

识别的音域、采样率、hop、阈值、分段参数与 HumTrans 验证集选择结果保持一致；没有重新调参或重跑保留测试集选参数。

## 可复现的前后对比

环境为 Node v24.19.0、Windows x64。固定 100 条灵感，每条 500 个音符；交错运行旧版、新版各 5 次，时间取中位数。桥接传输量按 `JSON.stringify(patch)` 的 UTF-8 字节数计算。

| 项目 | 优化前 | 优化后 |
| --- | ---: | ---: |
| 首页同步执行的模块数 | 10 | 3 |
| 这些模块的源码合计 | 65,918 B | 31,566 B |
| 首页首次视图传输 | 4,821,481 B | 12,802 B |
| 已有索引时，新首页的数据准备 | 75.30ms | 0.75ms |
| 记录未变化，返回首页的视图传输 | 4,821,481 B | 0 B |
| 500 音符编辑页首次视图传输 | 238,774 B | 130,112 B |
| 连续 40 次上下拖动的视图传输 | 9,552,220 B | 23,295 B |
| 每次拖动的逻辑处理，中位数 | 2.47ms | 0.39ms |

首页首次传输约减少 99.73%，该组拖动传输约减少 99.76%。模块源码合计表示实际同步 require 的依赖，并不表示微信下载包大小。数据准备与拖动逻辑时间包含 Node mock 的数据复制/序列化；它们不是手机冷启动耗时或帧率。首次打开旧版记录本会重建一次摘要，后续才能使用轻量索引。拖动松手后若音域范围改变，会进行一次必要的网格与音符位置重排。

识别 benchmark 使用固定合成音频，单项内部多轮取中位数：

| 项目 | 优化前 | 优化后 |
| --- | ---: | ---: |
| YIN 600 帧，8kHz，7 轮 | 241.34ms | 16.77ms |
| 4.44 秒录音完整识别，5 轮 | 202.67ms | 2.45ms |
| 29.5 秒、40 音符录音完整识别，5 轮 | 1,270.91ms | 15.80ms |

完整识别的提升同时来自计算减少与取消固定次数的等待。合成录音、桌面 V8、手机微信和自然人声的耗时会不同，不能把这些倍数当成所有手机和录音的提速保证。

原始 10 份模型基准、聚合结果、识别 benchmark 和源码 SHA-256 位于 [performance](performance/summary.json)。这些文件保留性能优化轮次的代码与结果快照；后续功能更新另见 [创作与音频分享](创作与音频分享.md)。

## 正确性验证

- 性能优化轮次结束时 `npm test` 全部通过：79 组命名检查，覆盖核心编辑、MIDI、麦克风授权、索引迁移/失败恢复、增量视图、试听缓存/取消/乱序写入和识别等价；后续创作与音频分享更新后共 107 组检查。
- 2,712 个 YIN 帧逐值一致，包含清音、谐波、颤音、噪声、DC、边界、短输入和尾部；4/8/16kHz 完整识别的音符、置信度与时长一致，比较时忽略随机 ID。
- 对 HumTrans 的 1,542 条已有缓存重新验证生产后处理；另重跑 4 条完整 TRAIN 录音，均与原评测输出逐音一致。结果见 [runtime-parity.json](performance/runtime-parity.json)。历史保留测试集统计没有改写。
- 两种音色的同步/异步合成样本一致，WAV 编码字节一致；重复试听不重新写文件，BPM/音色变化正确失效，过期异步写入不会替换新播放。

## 复现

工程根目录无需安装依赖：

```powershell
npm test
npm run benchmark
```

单独测量当前首页/编辑器模型并写出结果：

```powershell
node tools/performance-benchmark.cjs --out report.json
```

若保留了优化前完整 miniprogram 目录，可用 `--root` 指向它，以同一工具重跑旧版。源码包中的 `tools/performance-baseline/pitch.js` 单独冻结本轮识别优化前的实现，让识别等价测试与 benchmark 无需工作缓存即可运行；它与 HumTrans 调参前的 `tools/baseline/pitch.js` 用途不同。
