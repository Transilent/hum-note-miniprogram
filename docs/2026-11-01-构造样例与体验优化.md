# 构造样例回归与性能、体验优化

验证日期：2026-11-01。环境：Windows x64、Node.js v24.19.0、微信开发者工具 2.02.2608080、基础库 3.7.12；模拟器为 390 × 753px 窗口。构造音频不经麦克风采集。

## 本轮修正

- 钢琴卷帘和音符清单按可见窗口渲染，保留前后预渲染区域；完整音符与视图模型留在逻辑层。视图只接收音符总数、当前音符、可见窗口和网格，500 音符不会再被完整复制到 WebView。连续滚动使用 32ms 节流，滚动未结束时也持续补齐窗口。
- 进入宽音域乐句时按选中音符定位；长休止、缩放、清单最后一行和拖出旧窗口的音符仍可访问。拖动时值与数值输入统一支持 0.125–32 拍。
- 将长旋律缩为短旋律时，卷帘与清单偏移会收敛到新内容范围，不会留下超大占位或空白窗口。音频启动同步失败时也立即释放原生上下文与定时器。
- 编辑器与创作页区分“正在准备”和“正在播放”；生成声音期间再次点按可取消。非法 BPM、起始拍和时值会恢复最后有效显示，避免屏幕数字与实际音符不一致。
- 每个播放源拥有独立音频上下文和代次检查。旧源的结束、错误、时间与时长事件不能污染新源；停止、换源、离页、迟到写入和重入回调不会遗留定时器。两种音色的正常采样与 WAV 编码保持逐字节一致。
- 重叠检测改为排序、二分计数和前缀终点判断，避免逐一访问密集重叠的所有音符对。临时重叠仍可拖动、试听和保存草稿，正式保存及导出继续阻止。
- 原始录音的 WAV 编码分段让出事件循环。异步保存后重新检查页面状态，离页时清理本次生成的音频，不再写记录或跳转。
- 首页返回时保留已加载分页深度，入口防连点并提供导航失败反馈；创作预设切换合并页面更新，来源选择使用摘要。长标题可收缩、省略，预览和另存保持原记录与原录音独立。

## 同一批样例的前后测量

基线为本轮修改前代码快照。首页为 100 条、每条 500 个音符；拖动为同一音符连续 40 次上下移动。新旧版本交错各运行五轮，表中取中位数。传输量为实际 `setData` 参数 JSON 的 UTF-8 字节数。

| 项目 | 本轮之前 | 本轮之后 |
| --- | ---: | ---: |
| 500 音符编辑页首次传输 | 130,112 B | 35,832 B |
| 同一样例初始音符循环节点 | 1,000 | 126（78 卷帘 + 48 清单） |
| 40 次拖动页面更新调用 | 80 | 40 |
| 40 次拖动传输量 | 23,295 B | 21,698 B |
| 每次拖动模型处理 | 约 0.4ms | 约 0.3ms |
| 首页首次摘要传输 | 12,802 B | 12,802 B |
| 无内容变化返回首页 | 0 B | 0 B |

另一组 500 音符、MIDI 21–108 宽音域并含长休止的样例，初始仅挂载 65 个音符节点（17 卷帘 + 48 清单）；节点数随实际可见音域和缩放变化，完整 500 音符均保留并可编辑。

500 音符全重叠及嵌套样例共有 124,750 对重叠。单独热身后七轮、每轮百次的中位数由约 1.8ms 降至约 0.014ms；普通无重叠样例约 0.006ms，基本持平。240 组固定种子随机差分覆盖 7,721 个音符、48,311 对重叠，与独立二次 oracle 一致。

这些是桌面逻辑执行和桥接载荷测量，不能换算成手机冷启动耗时或帧率。首页暖启动模型准备约 0.8ms，本轮没有宣称首页启动倍数提升。原始结果见 [benchmark-summary.json](quality-20261101/benchmark-summary.json) 和 [benchmark-rounds.json](quality-20261101/benchmark-rounds.json)。

## 构造语料与完整回归

`npm test` 目前包含 142 组命名检查，另有 2,712 个 YIN 帧逐值等价比较。新增和扩展检查包括：

- 单音、不等时值和休止、MIDI 21/108 音域边界、500 音符上限、恰好 120 秒、长标题、嵌套和同起点重叠。
- 240 组固定种子差分，以及 `1e-6` 容差两侧、相接边界、乱序和重复 ID。
- 独立 MIDI 读取器核对 480 PPQ、BPM、音高、起点、时值、力度及 note on/off 配对。
- 8k/16k/44.1k/48k 的静音、固定噪声与带谐波、轻颤音的已知六音旋律。四种采样率的已知旋律均匹配 6/6，静音和噪声均无伪旋律。
- 持续滚动期间补齐可见窗口、访问第 500 行、输入回退、32 拍拖动、40 步撤销、播放准备取消、100 次快速换源、迟到事件与写入失败。
- 从已滚到末尾的 500 音符变成 8 音时，清单与卷帘立即可见；原生 `play()` 同步抛错后不保留播放请求、上下文或定时器。
- 两分钟合成音频、密集临时重叠和长静音的同步/异步采样及 WAV 字节一致；原始录音分段编码仍与同步编码逐字节一致。
- 预设、源数据不变、另存独立原录音、满额、复制/保存/导航失败、离页清理和原权限分类。

语料生成和识别结果仅用于验证信号链与回归，不等于真人哼唱准确率。此前 HumTrans 的参数与保留评测没有重新选择或改写。

## 微信模拟器集成

| 实际运行项目 | 结果 |
| --- | --- |
| 500 音符展开、缩放、选择 | 完整音符数保持 500，可见窗口随视口变化，初始选中音符进入可见音域 |
| 横向触摸移动 | 第二音从 0.125 拍移到 0；允许与第一音重叠，第三音仍为 0.25 拍 |
| 重叠导出、撤销与保存 | 导出被阻止且无成功弹窗；撤销后第二音恢复 0.125 拍，保存成功 |
| 500 音符试听 | 首次声音准备约 476ms，缓存再次准备约 19ms；实际音频处于播放状态 |
| 播放进度 | 两秒采样收到 66 次进度更新，最大相邻间隔 47ms；末次显示 1.5705 秒、音频 1.5993 秒，相差约 29ms |
| 合成哼唱完整链路 | 3.36 秒、16kHz 六音 WAV 经真实录音结束处理，约 140ms 完成解码、识别和保存，得到 `[60,62,64,67,69,67]` 并进入编辑页 |
| 实际 MIDI 导出 | 98 字节；取回字节独立解析为 6 音、100 BPM、480 PPQ，起点和时值在一 tick 内一致，见 [midi-verification.json](quality-20261101/midi-verification.json) |
| WAV 分享准备 | 当前旋律 148,220 字节；原始哼唱 107,566 字节，关闭弹窗保留原录音 |
| 创作应用与撤销 | 逆行追加由 6 音变为 12 音，跨页通道应用成功并保存；撤销回到原来的 6 音 |
| 另存 | 12 音写入新灵感，原录音独立复制到新路径，原记录保留 |

模板、样式编译和当前页面运行均通过。模拟器测试使用有明确前缀的独立样例及单独追踪的合成录音；测试结束后仅清理本轮记录、草稿和测试文件，不清空小程序存储。

取证时另遇到开发者工具热重载新增 SWC 辅助模块缺失的错误。编辑器的对象合并已改为 `Object.assign`，并清理编译缓存、完整编译后重新打开实际页面验证；最终错误日志无匹配。该处理未清理用户存储或授权状态。

手机微信的首次授权、真实麦克风采集、触控手感、系统打断和文件转发仍需真机验证，本轮没有代替用户授权或发送文件。

## 复现

工程根目录无需安装依赖：

```powershell
npm test
npm run benchmark
node tools/quality-fixtures.cjs list
node tests/quality-round.cjs
```

语料工具既可作为模块引用，也可单独输出样例：

```powershell
node tools/quality-fixtures.cjs dense-500 --full --json
node tools/quality-fixtures.cjs audio-harmonic-vibrato --rate 48000
```
