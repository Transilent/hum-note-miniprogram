# 哼记 · 灵感记录本

把短短一段哼唱，变成可以试听、编辑和带进编曲软件的 MIDI。

这是微信原生小程序原型，界面采用暖白与草木绿的记录本风格。录音、旋律识别、试听合成和灵感保存均在设备本地完成，不需要后端服务、API Key 或模型下载。

## 直接打开

工程已经通过本机微信开发者工具的官方命令行导入，并使用你确认的 AppID `wx7adc60ff4f038406` 做本地测试。尚未向微信平台上传或发布小程序；GitHub 仓库用于源码管理。

仓库：[Transilent/hum-note-miniprogram](https://github.com/Transilent/hum-note-miniprogram)。本机私有开发者工具配置、临时文件、头像设计原图和 HumTrans 原始数据集不在仓库中；项目功能说明与界面截图均已保留。

若重新导入，在微信开发者工具中选择本文件所在目录，也就是包含 `project.config.json` 的 `hum-midi-miniprogram` 文件夹。不要单独选择里面的 `miniprogram` 文件夹。

无需 `npm install`，也无需点击“构建 npm”。入口为 `miniprogram/pages/index/index`。

## 怎么使用

1. 点击“先听听一段示例”，可以立即体验编辑和试听。
2. 在首页点击麦克风，允许录音后，哼唱 2～15 秒。单次最长 30 秒；再次点击完成录音。
3. 识别完成后会自动保存灵感并进入编辑页。录音太轻、环境太吵或没有稳定音高时，会提示重新录制。
4. 在钢琴卷帘中点选音符，或点击音符清单中的一行自动跳到编辑卡片。左右拖动改变起点（按 1/8 拍吸附），上下拖动改变音高；也可用 `− / ＋` 每次升降一个半音。在“起始拍”输入框中可以精确输入位置，第 1 拍对应录音开头；调整起点即可缩短或拉长中间留白。输入数字后点击空白处或键盘完成键生效。
5. 拖动选中音符右侧边缘，或选择时值预设、输入拍数。时值允许 0.125～32 拍，可继续精调增值预设产生的长音符。移动和修改时值只影响当前音符，其他音符不会被自动推开。
6. 试听旋律，或对比原始哼唱。可切换木质琴音、柔和正弦两种合成音色。
7. 点击右上角 BPM 数字修改速度。钢琴卷帘支持“展开编辑”和 50%～200% 横向缩放；展开时仍可试听，点击“数值精调”回到编辑卡片。也可整体升降八度、对齐到 1/4 拍、手动添加或删除音符。编辑支持最多 40 步撤销/重做，并自动保存。
8. 点击“导出 MIDI”。在手机微信里，可通过“发送到微信”选择文件传输助手，再在电脑上导入 Cubase、Logic、FL Studio 等支持 MIDI 的软件。
9. 点击“分享音频文件”，选择按当前 BPM/音色合成的旋律 WAV，或已保存的原始哼唱 WAV。确认文件信息后再发送。
10. 顶部“旋律创作”分页可使用重复、逆行、倒影、逆行倒影、移调、增值、减值和动机重复。默认把变化后的副本接在原曲末尾，也可只保留变化后的整段。先试听，再应用到当前旋律或另存为新灵感。应用后支持撤销；另存会保留原记录并复制原哼唱文件。首页也有独立创作入口。

完整的手法调研、具体规则和界面见 [创作与音频分享](docs/创作与音频分享.md)。

编辑过程中允许音符暂时在时间上重叠。冲突音符会变色，页面提示“重叠，无法保存”；这时仍可继续移动、改时值、撤销、重做和试听，保存与 MIDI 导出会被阻止。未完成的布局会作为独立本地草稿暂存，重新进入该灵感时恢复，首页会标记“有未完成草稿”。消除重叠后自动保存新版本并清除草稿；上次有效保存的版本在此之前保持完整。

首页长按一条灵感，可在确认后删除它。原型最多保留 100 条本地灵感，每条最多 500 个音符，编辑后最长 2 分钟。删除小程序本地数据会同时清除灵感；需要保留的旋律应及时导出。

首页每批展示 20 条摘要，上拉继续载入。已有灵感会自动建立轻量索引，返回首页时没有变化就不重复刷新；录音识别与试听在首次使用时加载。编辑采用增量更新，试听支持缓存与分段合成。详细实测和复现方法见 [性能优化报告](docs/性能优化报告.md)。

## 当前识别范围

- 面向一个人、一条旋律的清晰哼唱，不支持同时识别伴奏、和弦或多人声音。
- 当前采用经 HumTrans 验证选择的 YIN 与稳健音符分段，检测约 40～1400 Hz。包含轻声门限、5 帧中值、稳定音确认、受音量约束的短漏检桥接，以及保守的同音重复起音检测。结果落到最近的十二平均律半音。
- 默认以 **100 BPM** 把录音秒数换算为拍数。这是初始编辑速度，不是自动测出的节拍。修改 BPM 会改变 MIDI 及合成试听速度，原始录音保持原速。
- 颤音、滑音、气声、噪声可能导致多余音符或八度误判。同一音高的连唱可能被合并，需要手动补充音符。
- 录音时的波形是录音状态动画；不是实时音量测量或实时音高识别。旋律识别在录音结束后进行。
- 已用 721 条真人哼唱选择配置，并在保留的 701 条录音上评测。音符起音 F1 和音高类别帧召回有所提高，帧精确率有所下降，旋律顺序基本持平。完整结果见 [真人哼唱评测摘要](docs/HumTrans评测摘要.md)。

## 真机录音和文件转发

开发者工具的麦克风、录音格式和文件转发行为与手机存在差异。模拟器能编译、编辑、试听和生成 `.mid` 文件。用户已在真机确认 MIDI 发送功能正常；麦克风授权修复和新版游标仍需在用户手机上复测。

用该 AppID 做手机测试之前，需在小程序后台完成与录音相关的用户隐私保护指引配置。代码已包含 `scope.record` 用途说明、隐私指引入口以及同意/拒绝处理。手机首次录音时由用户亲自同意隐私授权和麦克风权限。

新版先完成隐私授权，再查询小程序与微信系统麦克风状态。首次使用或授权状态未知时，由 `RecorderManager.start` 发起实际录音授权；只有已确认拒绝过小程序权限才提供小程序设置入口，系统麦克风被拒绝则提供微信系统权限入口。失败提示保留原始错误，并区分隐私接口未声明、隐私授权未同意、权限关闭及录音器错误，不再把所有错误都跳转到空白的权限记录页。模拟器只读查询得到 `scope.record` 尚未出现、系统麦克风已授权；它不能代替手机授权结果。

播放游标由真实 `onPlay` 事件启动，每约 33ms 读取/插值音频时间；缓冲、暂停、停止时暂停或清理计时。音频时间持续校准位置，生成试听文件期间不会提前走动，长旋律播放时横向跟随。

录音以 WAV 请求；解析时读取实际 WAV 头的采样率和声道数，支持 PCM 及 float32 WAV。遇到某些开发者工具返回的压缩格式时，尝试用微信 WebAudio 解码，不会把压缩数据误当 PCM。原始试听内容会另存为规范 WAV。

MIDI 使用标准格式 0、480 ticks/quarter、4/4 拍号、独立 tempo 事件和配对的 note on/off。MIDI 保存的是音符，不携带原始人声或合成音色采样。

## 验证

在安装 Node.js 18 或更新版本的电脑上，在工程根目录执行：

```powershell
npm test
```

该命令执行应用与编辑回归测试、独立 MIDI/评测指标测试。测试没有第三方依赖，不调用网络或麦克风。

当前共 107 组命名检查通过，另含 2,712 个 YIN 帧逐值等价对比。执行 `npm run benchmark` 可复现桌面性能测量；这些时间不代表手机冷启动或帧率。

测试覆盖音域扩展、轻声、音高抖动、同音起音、清晰休止、不同采样率、横向编辑、缩放拖动、草稿恢复、音频进度时钟、录音授权分类、MIDI 写出，以及独立解析、最大匹配、八度、时间容差和作品宏平均。

实际开发者工具的验证结果与限制见 [验证记录](docs/验证记录.md)。

```text
hum-midi-miniprogram/
  project.config.json          开发者工具入口
  miniprogram/
    app.js / app.json / app.wxss
    pages/index/               录音、示例、灵感记录本、隐私授权
    pages/editor/              轨迹编辑、时值音高、试听、导出
    pages/compose/             旋律发展预设、对比试听、应用与另存
    utils/composition.js       纯函数旋律变形引擎
    utils/audio-export.js      旋律与原始哼唱 WAV 分享准备
    utils/pitch.js             本地 YIN 与音符分段
    utils/pitch-config.js      验证集选定的固定识别参数
    utils/pitch-segmentation.js 稳定音符与重复起音分段
    utils/music.js             音乐数据和编辑变换
    utils/wav.js               WAV 读写
    utils/audio.js             解码、音色合成和播放
    utils/midi.js              标准 MIDI 写出
    utils/storage.js           本地灵感和录音保存
  tests/run.js                 无依赖核心验证
  tests/editor.js              实际编辑处理函数与草稿生命周期验证
  tests/humtrans-metrics.cjs    MIDI 解析与评测口径测试
  tools/                       无依赖 HumTrans 评测与原版基线
  docs/                        实际界面截图与验证记录
```
